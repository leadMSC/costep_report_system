# 설계 — 관리자 기능 · 고객 저장(계정) · 가입 신청 · 초대 · 퇴출

> 작성 2026-10-14 · 대상: MSC report (costepmsc-report.com) · 목업: `design/mockup-admin.html`
> 지금 있는 것 위에 얹는다: Supabase 표 `orgs · profiles · clients · assessments · documents · invites · audit_logs`, 역할 `pending · consultant · org_admin · operator · blocked`, 관리 화면 4탭(구성원 · 초대 · 접속 기록 · 펌 정보).

## 0. 한눈에

| 기능 | 지금 | 바꾸는 것 |
|---|---|---|
| 고객 저장 | 이 PC 브라우저(계정별로 나눔) | **계정(서버)에 저장** — 어느 PC에서 로그인해도 같은 고객. 이 PC 자료는 한 번에 올리기 |
| 가입 | 로그인하면 '승인 대기' 화면만 | **가입 신청서**(이름·연락처·소속 펌·새 펌/기존 펌 합류) → 운영자 또는 펌 관리자 승인 |
| 초대 | 이메일 사전 등록(로그인하면 바로 소속) | **초대 링크·만료·역할·상태(대기/수락/만료/취소)**, 다시 보내기 |
| 퇴출 | 차단만 있음(서비스 전체) | **펌에서 내보내기**(접속 즉시 차단 + 맡던 고객을 다른 사람에게 넘김) / 차단은 운영자만 |
| 관리자 | 4탭 | **운영자 콘솔**(펌·가입 신청·전체 사용자) + **펌 관리자 콘솔**(구성원·초대·고객·발행 대장·접속 기록·펌 정보) |

## 1. 역할과 할 수 있는 일

| 할 일 | 운영자 | 펌 관리자 | 컨설턴트 | 승인 대기 |
|---|:-:|:-:|:-:|:-:|
| 진단 작성·서식 발행 | ○ | ○ | ○ | × |
| 내 고객 보기·고치기 | ○ | ○ | ○ | × |
| 펌 고객 전체 보기 | ○ | ○ | 결정 ①에 따름 | × |
| 고객 담당자 바꾸기 | ○ | ○ | × | × |
| 구성원 초대·역할 변경·퇴출 | ○ | 자기 펌만 | × | × |
| 기존 펌 합류 신청 승인 | ○ | 자기 펌만 | × | × |
| 새 펌 만들기 신청 승인 | ○ | × | × | × |
| 서비스 전체 차단·해제 | ○ | × | × | × |
| 접속 기록 보기 | 전체 | 자기 펌 | 내 것 | × |

- 펌 관리자는 자기 자신을 퇴출하거나 펌의 마지막 관리자를 강등할 수 없다(펌이 관리자 없이 남지 않게).
- 운영자 권한은 운영자만 준다(지금 규칙 유지).

## 2. 가입 신청 (초대 없이 처음 로그인한 사람)

흐름: 구글 로그인 → (초대 있음) 바로 소속·역할 적용 → 시작 / (초대 없음) **가입 신청서** → 승인 대기 화면 → 승인되면 다음 로그인에 바로 시작, 거절되면 사유 표시.

신청서 칸: 이름 · 휴대폰 · 직함 · **소속 방식**(새 펌 만들기 / 기존 펌에 합류) · 펌 상호 · 사업자등록번호(새 펌일 때, 검증식) · 합류할 펌 코드(기존 펌일 때 — 펌 관리자가 알려 주는 6자리) · 하고 싶은 말 · 개인정보 처리 동의(필수).

- 새 펌 신청 → **운영자** 승인: 펌 생성 + 신청자 = 펌 관리자.
- 기존 펌 합류 신청 → **그 펌 관리자**(또는 운영자) 승인: 신청자 = 컨설턴트.
- 거절 시 사유(선택) 기록, 같은 계정은 7일 뒤 다시 신청 가능.
- 남는 대기자: 30일 지나도 처리 안 되면 운영자 콘솔 맨 위에 표시.

DB: 새 표 `org_requests(id, user_id, kind[new_org|join], org_name, biz_no, org_code, applicant_name, phone, title, message, status[pending|approved|rejected|cancelled], decided_by, decided_at, reason, created_at)` · 함수 `approve_org_request(id)`, `reject_org_request(id, reason)` (security definer, 감사 기록) · `orgs` 에 `join_code text unique`(펌 코드, 관리자가 다시 만들 수 있음).

## 3. 초대

- 펌 관리자가 **이메일 + 역할(컨설턴트/펌 관리자)** 로 초대 → 초대 링크 생성(만료 7일) → 링크 복사·메일 문구 복사(메일 발송은 사용자가 직접 — 서비스가 대신 보내지 않음).
- 초대받은 사람이 그 구글 계정으로 로그인하면 바로 소속·역할 적용(지금 동작 유지). 링크로 들어오면 '○○펌 초대' 안내가 먼저 보인다.
- 상태: 대기 · 수락 · 만료 · 취소. 다시 보내기(만료 연장), 취소.
- 이메일이 다른 계정으로 로그인하면: "초대받은 이메일(a***@gmail.com)로 로그인해 주세요" 안내.

DB: `invites` 에 `token uuid unique, expires_at, status, accepted_at, accepted_by, created_by` 추가 · 함수 `accept_invite(token)` · 지금의 '첫 로그인 자동 적용'(handle_new_user)은 만료·취소된 초대를 건너뛰게 고친다.

## 4. 퇴출(펌에서 내보내기)과 차단

| | 펌에서 내보내기 | 차단 |
|---|---|---|
| 누가 | 펌 관리자·운영자 | 운영자만 |
| 결과 | 그 펌 고객·발행 문서에 즉시 접근 불가, 계정은 '소속 없음'(다른 펌 합류 신청 가능) | 서비스 전체 로그인 불가 |
| 맡던 고객 | **넘겨받을 구성원을 반드시 고름**(펌 관리자 기본) — 고객·진단의 담당자가 바뀜 | 그대로(펌 소유) |
| 되돌리기 | 다시 초대 | 차단 해제 |

- 고객·진단·발행 문서는 **펌 소유**다. 사람이 나가도 펌에 남는다(작성자 기록은 그대로).
- 처리 순서(한 번에, 함수 `remove_member(user_id, transfer_to)`): 담당자 이관 → 역할 'pending'·소속 비움 → 감사 기록(누가·언제·이관 대상·이관 건수). 열려 있던 세션은 다음 저장·조회 때 권한 확인에서 막힌다.
- 확인창: "홍길동님을 ○○펌에서 내보냅니다. 맡던 고객 12곳은 김OO님에게 넘깁니다. 되돌리려면 다시 초대해야 합니다."

## 5. 고객 저장(계정)

- 저장 단위: **고객(clients)** 1 — **진단(assessments)** 여럿(회차). 화면 입력 전체는 지금처럼 `collectFormData()` 결과 하나를 `assessments.form_data` 에 넣는다(구조 변경 없음).
- 자동 저장: 입력 멈춘 뒤 2초에 서버 저장(지금 이 PC 자동 저장과 같은 시점). 저장 표시: 저장 중 · 저장됨 · 연결 끊김(이 PC에 임시 보관 → 다시 연결되면 올림).
- 동시 편집: `updated_at` 비교 — 다른 사람이 먼저 고쳤으면 "다른 곳에서 바뀌었습니다: 새로 불러오기 / 내 것으로 덮기" 고르기.
- 고객 목록(2뎁스 「기존 고객 불러오기」): 검색(상호·사업자번호·대표자) · 정렬(최근 수정) · 담당자 · 진단 회차 · 마지막 발행일. '내 고객 / 펌 전체'(결정 ①).
- 같은 사업자번호 중복 막기: 새 고객 만들 때 펌 안에 같은 번호가 있으면 "이미 있는 고객입니다 — 불러오기".
- **이 PC 자료 올리기**: 로그인 후 한 번 안내 — 이 PC에 저장된 고객 n곳을 계정으로 올림(중복은 건너뜀), 올린 뒤 이 PC 사본 지우기 선택.
- 삭제: 펌 관리자만. 30일 휴지통 뒤 완전 삭제(운영자가 복구 가능).
- 개인정보: 고객 등록 때 '개인정보 수집·이용 동의 받음' 확인칸(필수) · 보관 기간(결정 ②) 지나면 운영자 콘솔에 파기 대상으로 표시 · 열람·수정·삭제 모두 감사 기록.

DB: `clients` 에 `assigned_to, biz_no_norm(숫자만, 펌 안에서 unique), ceo_name, consent_at, consent_by, deleted_at` · `assessments` 에 `round int, updated_by, version int` · 정책: 읽기/쓰기는 결정 ①에 맞춰 `assigned_to = auth.uid()` 또는 펌 전체 · 함수 `reassign_clients(from, to)`.

## 6. 관리자 화면

- **운영자 콘솔**: 가입 신청(새 펌·합류) · 펌 목록(구성원 수·고객 수·최근 활동) · 전체 사용자(차단·해제) · 파기 대상 · 접속 기록.
- **펌 관리자 콘솔**(지금 관리 창 확장): 구성원(역할 변경·내보내기) · 초대(링크·상태) · 합류 신청 · 고객(담당자 바꾸기·삭제) · 발행 대장(문서번호·서식·발행자·날짜) · 접속 기록 · 펌 정보(로고·직인·접두어·펌 코드).
- 열기: 왼쪽 아래 계정 상자 톱니바퀴 → 「구성원·펌 관리」(펌 관리자·운영자에게만 보임).

## 7. 결정 필요 (내일 시작 전에)

| # | 질문 | 권고 |
|---|---|---|
| ① | 컨설턴트가 같은 펌 다른 컨설턴트의 고객을 볼 수 있나 | **보기만 펌 전체, 고치기는 담당자와 펌 관리자** — 휴가·인수인계 때 막히지 않음 |
| ② | 고객 개인정보 보관 기간 | 마지막 진단 후 **3년**, 지나면 파기 대상 표시(자동 삭제는 안 함) |
| ③ | 동의 문구 | 코스텝이 정한 문구 사용(시트 '코스텝 결정 사항'에 이미 있음) — 받기 전엔 표준 초안으로 시작 |
| ④ | 구글 로그인 앱 '게시' | 컨설턴트를 늘리려면 필요(지금은 등록한 테스트 사용자만 로그인) — 개인정보처리방침 페이지가 있어야 함 |

## 8. 작업 순서(내일)

1. 마이그레이션 4개(초대 확장 · 가입 신청 · 고객 저장 칸 · 퇴출·이관 함수) — Supabase SQL 편집기에 적용(사용자가 붙여 넣기), 정책 조회로 확인
2. 가입 신청서·승인 대기 화면
3. 초대 링크·상태
4. 고객 서버 저장 + 이 PC 자료 올리기 + 고객 목록
5. 관리자 콘솔(펌 관리자 → 운영자)
6. 퇴출·차단·담당자 이관
7. 시험: 두 계정(관리자·컨설턴트)으로 초대→수락→고객 저장→다른 PC에서 열기→퇴출→접근 막힘 확인, 기존 회귀 시험 전부
