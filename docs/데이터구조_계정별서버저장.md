# 계정별 서버 저장 — 데이터 구조 (Supabase)

2026-10-14 · 작업로그 L-094 · SQL: `supabase/migrations/20261014000001_account_data.sql`

## 지금 문제
- 「내 정보」(소속 펌·나)와 「고객 저장」이 **이 PC 브라우저에만** 저장된다. 다른 PC·관리자 화면에서 안 보이고, 브라우저를 지우면 없어진다.
- 서버 표(orgs·profiles·clients·assessments)는 10-12에 만들어 두었지만 앱이 아직 펌 정보 일부만 쓴다.
- 운영자 계정(leadbzcenter)은 소속 펌이 비어 있어 '리드엠에스씨'를 서버에 둘 곳이 없다.

## 구조

```
auth.users (구글 로그인)
   │ 1:1
profiles  나 ─────────────┐ org_id
   이름·직함·휴대폰·연락메일·역할      │
                          ▼
orgs  펌(소속) ── 1인 컨설턴트도 자기 펌 1개(kind=solo)
   상호·문서번호 접두어·대표·전화·주소·검토자·결재권자·로고·직인·사업자번호
   │ 1:N
clients  고객사 ── owner_id = 담당 컨설턴트
   상호·사업자번호(숫자만 → 펌 안 중복 금지)·잘 안 바뀌는 정보(profile)
   │ 1:N
assessments  진단 건 ── consultant_id, 회차, version
   form_data = 화면 입력 전체(collectFormData 결과 그대로) · 규모·업종 · 상담 목적 · 초안/확정
   │ 1:N
documents  발행 대장(이미 있음) · audit_logs 기록(이미 있음)
```

## 화면 칸 → 서버 자리

| 화면 | 칸 | 서버 |
|---|---|---|
| 내 정보 > 소속 펌 | 상호 / 문서번호 접두어 / 대표 / 대표 전화 / 주소 | orgs.name / doc_prefix / ceo_name / phone / address |
| | 검토자 / 결재권자 / 로고 | orgs.reviewer_label / approver_label / logo_path |
| (관리 화면) | 직인 · 홈페이지 | orgs.seal_path · homepage |
| 내 정보 > 나 | 이름·직함 | profiles.name · title |
| | 휴대폰 / 메일 | profiles.phone / contact_email |
| 고객사 정보 | 상호 · 사업자번호 | clients.name · biz_no |
| | 대표·개업일·소재지·업종 등 잘 안 바뀌는 것 | clients.profile (JSON) |
| 고객 저장(화면 전체) | collectFormData() | assessments.form_data (+ biz_track·industry_track·report_keys) |

## 누가 무엇을 보나 (서버가 막음, RLS)
- **컨설턴트**: 자기가 만든 고객·진단 건만 읽고 고침
- **펌 관리자**: 자기 펌 전체 + 펌 정보 수정
- **운영자**: 전체
- 지우기는 휴지통(deleted_at)으로, 완전 삭제는 펌 관리자만
- 소속 펌이 없는 승인 계정은 `create_my_org(상호, 접두어)` 로 자기 펌을 만들고 그 펌 관리자가 된다(운영자는 운영자 그대로)

## 저장 흐름 (앱)
1. 로그인하면 서버의 펌·나 정보를 「내 정보」에 채운다. 고치면 서버에 저장(펌 정보는 펌 관리자·운영자만, 컨설턴트는 읽기).
2. 「고객 저장」 = 고객(clients) 찾기/만들기(사업자번호 기준) → 진단 건(assessments) 저장. 자동 저장도 서버로(2초 묶음).
3. 다른 PC에서 먼저 고쳤으면(version 다름) 덮어쓰지 않고 「다른 곳에서 고친 내용이 있습니다 — 불러오기/내 것으로 저장」.
4. 이 PC에 저장돼 있던 고객은 「서버로 올리기」 단추로 한 건씩 옮긴다(자동으로 다 올리지 않음).
5. 로그인 안 한 로컬 시험 모드는 지금처럼 이 PC 저장.

## 주의
- 고객 자료에는 대표 생년월일·신용점수 같은 개인정보가 들어 있다. 서버 저장 전에 화면에 수집·보관 안내를 띄우고(동의 기록), 보관 기간·파기 방법을 정해야 한다(계획 WP-03b).
- 로고·직인은 지금처럼 그림 글자(data URL)로 펌 표에 저장 — 1MB 안쪽으로 줄여 저장한다.
