# 고객사 정보 페이지 재기획 (2026-10-21)

## 배경
- 요청: 참고 화면(「01 기업 일반 현황 및 핵심 인프라」)처럼 고객 정보를 한 페이지에서 받되, **새 폼을 덧붙이지 말고 기존 칸과 겹치는 것은 한 번만 적게** 페이지를 다시 짠다. 업종은 자유 기재(주유소·화훼처럼 정해진 10개 업종에 없는 경우), 칸마다 예시, 펼치면 대표자 주민등록번호 칸, 서류 업로드로 자동 채우기, 항목명·내용을 직접 적는 「기타」 칸.
- 현황(실측): 입력 칸 148개 / 8단계. 고객사 정보 단계 13칸, 나머지 기업 정보가 진단 대상·거래처·인증·실태·재무·업종 특화·사업계획에 흩어져 있고 같은 내용을 두세 곳에서 묻는다.
- 원칙: ① 한 사실은 한 칸(나머지 단계·서식은 그 칸을 읽기만) ② 불변 → 가변 순서 ③ 서류로 채울 수 있는 칸은 서류 먼저, 사람은 빈칸·확인만 ④ 기존 저장 자료는 새 칸으로 자동 이전(버전 올림) ⑤ A4 서식 출력은 지금 모양 유지.

## 3. 대표자 주민등록번호 — 권고: 앞 7자리까지만
- 개인정보 보호법 제24조의2: 주민등록번호는 **법령에 근거가 있을 때만** 처리할 수 있고, 본인 동의로는 근거가 되지 않는다. 경영컨설팅 기록에는 그 근거가 없어 **전체 13자리 저장은 법 위반 위험**이 크다(서버 저장·PDF 출력까지 하므로 더 큼).
- 지금 앱도 서류에서 읽을 때 뒷자리를 즉시 지운다(redact).
- 권고: 「생년월일 + 성별 자리」(예: 800101-1******)만 받는 칸. 나이·성별(여성기업·청년 우대)은 여기서 계산. 정책자금 신청서에 전체 번호가 필요하면 신청 단계에서 고객이 직접 기재.
- 사용자 결정 필요(아래 6).

## 6. 결정이 필요한 것
1. 주민등록번호: **앞 7자리만(권고)** / 전체 13자리(법적 근거·암호화·출력 제외 필요).
2. 주업종 '기타'를 허용하고 지원사업 매칭은 가장 가까운 분류로 추천(권고) / 업종 목록 자체를 늘림(주유소→에너지 소매, 화훼→농업 등).
3. NICE·KCB·상시근로자 수를 고객사 정보로 옮기고 소상공인도 받기(권고).

## 7. 진행 순서(승인 후)
1. 칸 사전(FIELD_REGISTRY)에 중복 통합 결과 반영 + 저장 자료 v2 이전 함수(옛 칸 값 → 새 칸, 손실 없음)
2. 고객사 정보 페이지 재배치(위 4) — impeccable(Operate) 로 배치, 기존 색·글꼴 유지
3. 새 칸 + 서류 연결(업태/종목 분리, 성별 자리, 주주 목록, 임대차→점유)
4. 기타 항목 행 + 업종별 예시 칩, 서식2 '기타' 표 출력
5. 업종 특화·실태·사업계획 단계에서 중복 칸 제거(읽기 전용 표시로 대체)
6. 검증: 시나리오·PDF·break-ui(긴 항목명·행 20개)·옛 저장 자료 불러오기 이전 시험
